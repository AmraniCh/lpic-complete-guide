# 109.2 Persistent network configuration

**Weight: 4**

Candidates should be able to manage the persistent network configuration of a Linux host.

**Objectives**

- Understand basic TCP/IP host configuration
- Configure ethernet and wi-fi network configuration using NetworkManager
- Awareness of systemd-networkd

**Terms**

`/etc/hostname`, `/etc/hosts`, `/etc/nsswitch.conf`, `/etc/resolv.conf`, `nmcli`, `hostnamectl`, `ifup`, `ifdown`

### Persistent versus temporary

Every host needs an IP configuration (address, netmask, default gateway, DNS) to work on a network. A laptop changes networks constantly and adapts; a server keeps the same settings for years and must survive reboots and upgrades. **Persistent** configuration is the kind that is written to files or a manager and comes back automatically, and it is what this objective is about.

### Network interfaces

The **NIC** (Network Interface Card) is the network hardware. Old kernels named cards `eth0`, `eth1`, and so on in load order, which could change between boots. Modern names are stable and describe the device: `eno1` (on-board), `enp3s0` (PCI ethernet), `wlp108s0` or `wlan0` (wireless). `ip link show` lists them:

```
$ ip link show
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 ...
2: wlp108s0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 ...
    link/ether 00:bb:60:97:6b:07 brd ff:ff:ff:ff:ff:ff
```

`lo` is the **loopback**, a virtual interface always present, meaning "this machine" (`127.0.0.1`).

### Configuring interfaces the traditional way

Older systems used `ifconfig` to show and set addresses (root needed to change them):

```
$ ifconfig wlp3s0
wlp3s0: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 192.168.1.35  netmask 255.255.255.0  broadcast 192.168.1.255
# ifconfig enp0s25 192.168.42.42 netmask 255.255.255.0    # set address + mask
# ifconfig enp0s25 down                                   # bring it down
```

`ifup` and `ifdown` bring an interface up or down using saved settings (`ifup eth0`). Those saved settings live in files. On Debian, in `/etc/network/interfaces`:

```
auto eth0
iface eth0 inet static
    address 192.168.1.10
    netmask 255.255.255.0
    gateway 192.168.1.1
    dns-nameservers 4.2.2.4
```

On Red Hat, per interface in `/etc/sysconfig/network-scripts/ifcfg-eth0`:

```
DEVICE=eth0
ONBOOT=yes
IPADDR=192.168.1.10
NETMASK=255.255.255.0
DNS1=4.2.2.4
```

### The ip command

Recent systems use `ip`, which shows and changes addresses, links, and routes:

```
$ ip addr show eth2
# ip addr add 172.19.1.10/24 dev eth2      # add an address
# ip addr del 172.19.1.10/24 dev eth2      # remove it
# ip link set eth2 up                      # bring the link up
$ ip route show                            # the routing table
# ip route add default via 192.168.1.1     # set the default gateway
```

These changes are **temporary** and are lost at reboot or when NetworkManager restarts. For persistence, use the config files or NetworkManager.

### NetworkManager and nmcli

**NetworkManager** is the service that now manages networking on most desktops and servers. It watches the network and configures interfaces automatically, which is why a laptop reconnects to known Wi-Fi and an ethernet cable gets an address at once, often through **DHCP** (Dynamic Host Configuration Protocol), where the machine asks a server for its IP, netmask, gateway, and DNS. NetworkManager controls any interface not listed in `/etc/network/interfaces`, and its settings are persistent.

`nmcli` is its command-line tool (there is also the text UI `nmtui`). It takes an object such as `general`, `device`, or `connection`:

```
$ nmcli general              # overall status
$ nmcli device               # interfaces and their state
$ nmcli connection show      # saved connections
```

Connect to Wi-Fi, or define a persistent static ethernet connection:

```
$ nmcli device wifi list
$ nmcli device wifi connect AxLTE password "AFunkyPassword"

# nmcli con add type ethernet con-name office ifname eth0 \
      ip4 192.168.1.10/24 gw4 192.168.1.1
# nmcli con mod office ipv4.dns "4.2.2.4 8.8.8.8"
# nmcli con up office
```

### Awareness: systemd-networkd

**systemd-networkd** is another manager, common on servers and containers. It reads `.network` files under `/etc/systemd/network/`. For LPIC-1 you only need to know it exists as an alternative to NetworkManager.

### The hostname

A hostname is a friendly name for a machine. The permanent one is in `/etc/hostname`, and `hostnamectl` sets it (updating the file and the running system at once):

```
# hostnamectl set-hostname mycoolmachine
# cat /etc/hostname
mycoolmachine
# hostnamectl status
   Static hostname: mycoolmachine
         Icon name: computer
```

`hostnamectl --transient set-hostname ...` sets a temporary name, and `--pretty` sets a descriptive label.

### /etc/hosts

`/etc/hosts` is a local, static table of addresses to names, checked before DNS. It always defines the loopback names, and you can add LAN machines:

```
127.0.0.1        localhost
::1              localhost
192.168.1.22     amoledtesting
198.74.56.50     jobs.jadi.net
```

It is the quick way to name a machine without running a DNS server.

### DNS client: /etc/resolv.conf

To turn names into addresses, the host needs DNS servers, listed in `/etc/resolv.conf`:

```
nameserver 192.168.1.1
nameserver 4.2.2.4
domain jadi.net
search jadi.net company.com
```

`nameserver` lines are the DNS servers to ask, in order. `search` lets a short name like `tv` be tried as `tv.jadi.net` then `tv.company.com`. On modern systems this file is often generated by NetworkManager or systemd-resolved, so you set the servers in the manager rather than editing it directly.

### Resolution order: /etc/nsswitch.conf

`/etc/nsswitch.conf` decides which source answers each kind of lookup. The `hosts:` line controls name resolution:

```
hosts:  files dns myhostname
```

`files` means check `/etc/hosts` first, then `dns` asks a DNS server. Reverse it to `hosts: dns files` and DNS is tried first, with `/etc/hosts` only as a fallback.

### Summary

I split networking into "what interface" and "what name". Interfaces have stable names like `enp3s0` and `wlp108s0`, shown with `ip link show`, plus the `lo` loopback. I can make a quick, temporary change with `ip addr add` and `ip route add`, but for persistence I use NetworkManager through `nmcli` (`device`, `connection`, `con add`/`mod`/`up`, `device wifi connect`), often via DHCP, and I know the legacy files `/etc/network/interfaces` (Debian) and `/etc/sysconfig/network-scripts/` (Red Hat) with `ifup`/`ifdown`, and that systemd-networkd is another option. For names, the host's own name is in `/etc/hostname` (set with `hostnamectl`), `/etc/hosts` is a static local name table checked before DNS, `/etc/resolv.conf` lists the DNS servers and search domains, and `/etc/nsswitch.conf` sets the order with its `hosts: files dns` line.
