# 109.2 Persistent network configuration

Candidates should be able to manage the persistent network configuration of a Linux host.

**Objectives**

- Understand basic TCP/IP host configuration
- Configure ethernet and wi-fi network configuration using NetworkManager
- Awareness of systemd-networkd

**Terms**

`/etc/hostname`, `/etc/hosts`, `/etc/nsswitch.conf`, `/etc/resolv.conf`, `nmcli`, `hostnamectl`, `ifup`, `ifdown`

### Persistent versus runtime

Commands like `ip addr add` change the network **now**, but the change is lost at the next reboot. **Persistent** configuration is stored in files or a manager so it comes back automatically. This objective is about the persistent side.

### The hostname

The machine's name is stored in `/etc/hostname`:

```
$ cat /etc/hostname
webserver01
```

Set it cleanly with `hostnamectl`, which updates the file and the running system at once:

```
$ hostnamectl set-hostname webserver01
$ hostnamectl
   Static hostname: webserver01
         Icon name: computer-vm
        Operating System: Debian GNU/Linux 12
```

### /etc/hosts

`/etc/hosts` is a local, static list of name to address mappings, checked before DNS. It always defines the loopback names:

```
127.0.0.1   localhost
127.0.1.1   webserver01
192.168.1.20   db.local db
::1         localhost ip6-localhost
```

It is the quick way to give a name to a machine on your LAN without running a DNS server.

### Name resolution order: /etc/nsswitch.conf

`/etc/nsswitch.conf` decides the order of sources for lookups. The `hosts:` line controls host name resolution:

```
hosts:  files dns
```

`files` means check `/etc/hosts` first, then `dns` means ask a DNS server. Swapping the order changes which source wins.

### DNS servers: /etc/resolv.conf

`/etc/resolv.conf` lists the DNS servers to query and the default search domain:

```
nameserver 192.168.1.1
nameserver 8.8.8.8
search example.com
```

On many modern systems this file is generated by NetworkManager or systemd-resolved, so you set the servers in the manager rather than editing the file directly.

### NetworkManager with nmcli

**NetworkManager** is the common way to manage connections on desktops and servers. `nmcli` is its command line tool, and its settings persist across reboots.

```
$ nmcli device status              # list interfaces and state
DEVICE  TYPE      STATE       CONNECTION
eth0    ethernet  connected   Wired 1
wlan0   wifi      disconnected --
$ nmcli connection show            # list saved connections
```

Give an interface a static address:

```
$ nmcli con add type ethernet con-name office ifname eth0 \
    ip4 192.168.1.20/24 gw4 192.168.1.1
$ nmcli con mod office ipv4.dns "192.168.1.1 8.8.8.8"
$ nmcli con up office
```

Connect to wi-fi:

```
$ nmcli device wifi list
$ nmcli device wifi connect "MyNetwork" password "secret123"
```

### Legacy ifup / ifdown

Older Debian systems configure interfaces in `/etc/network/interfaces` and bring them up or down with `ifup` and `ifdown`:

```
# /etc/network/interfaces
auto eth0
iface eth0 inet static
    address 192.168.1.20/24
    gateway 192.168.1.1
```

```
$ ifup eth0
$ ifdown eth0
```

### Awareness of systemd-networkd

**systemd-networkd** is another manager, common on servers and containers. It reads `.network` files under `/etc/systemd/network/`. For LPIC-1 you only need to know it exists as an alternative to NetworkManager.

### Summary

I separate runtime changes, which vanish at reboot, from persistent configuration, which is what this objective covers. The hostname lives in `/etc/hostname` and I set it with `hostnamectl set-hostname`. `/etc/hosts` is my static local name list, checked before DNS, and `/etc/nsswitch.conf` sets the order with its `hosts: files dns` line, while `/etc/resolv.conf` names the DNS servers, though a manager often generates it. For real configuration I use NetworkManager through `nmcli`: `nmcli device status` to see interfaces, `nmcli con add`/`mod`/`up` for a static wired address, and `nmcli device wifi connect` for wireless. I know the legacy path is `/etc/network/interfaces` with `ifup`/`ifdown`, and that systemd-networkd is a further alternative.
