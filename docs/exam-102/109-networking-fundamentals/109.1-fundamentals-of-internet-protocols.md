# 109.1 Fundamentals of internet protocols

**Weight: 4**

Candidates should demonstrate a proper understanding of TCP/IP network fundamentals.

**Objectives**

- Demonstrate an understanding of network masks and CIDR notation.
- Knowledge of the differences between private and public "dotted quad" IP addresses.
- Knowledge about common TCP and UDP ports and services (20, 21, 22, 23, 25, 53, 80, 110, 123, 139, 143, 161, 162, 389, 443, 465, 514, 636, 993, 995).
- Knowledge about the differences and major features of UDP, TCP and ICMP.
- Knowledge of the major differences between IPv4 and IPv6.
- Knowledge of the basic features of IPv6.

**Terms**

`/etc/services`, IPv4, IPv6, Subnetting, TCP, UDP, ICMP

### TCP/IP

**TCP/IP** is the stack of protocols behind most communication on the Internet. Although it is named after TCP, it also includes UDP, ICMP, DNS, and many others working together.

### IP addresses

The **Internet Protocol (IP)** gives each host a logical address so packets can be sent to it. Addresses must be unique on a network so packets reach the right place. There are two live versions, 4 and 6.

An **IPv4** address is `A.B.C.D`, where each part is 0-255:

```
192.168.1.4
1.1.1.1
100.0.0.100
```

Each part is an **octet**, an 8-bit number. With four octets there are 256^4 = about 4.3 billion addresses, which sounds like a lot but is not enough for the modern world, which is why IPv6 exists.

#### Private IP addresses

Public addresses are handed out through IANA and the regional registries. But your laptop, phone, and printer at home do not each buy a public address. Instead they use **private** ranges, which anyone may use as long as the devices are not directly on the Internet:

| Range | Size |
|---|---|
| `10.0.0.0` to `10.255.255.255` | ~16M addresses |
| `172.16.0.0` to `172.31.255.255` | ~1M addresses |
| `192.168.0.0` to `192.168.255.255` | ~65K addresses |

A **NAT** (Network Address Translation) device sits between the private network and the Internet with one public address. When a private device reaches out, NAT swaps in its own public address and hands the reply back:

```
 private network                         Internet
 192.168.2.100 ─┐
 192.168.2.200 ─┼─► [ NAT: 87.3.91.4 ] ─────► public servers
 172.16.1.2   ─┘        one public IP
```

So many devices share one public address, and nobody on the Internet can reach them directly unless a port is forwarded.

#### Subnetting and the netmask

Subnetting splits an address into a **network** part (shared by all devices on the segment) and a **host** part (unique per device). The split is written two ways: a decimal **netmask** like `255.255.255.0`, or **CIDR** (Classless Inter-Domain Routing) like `/24`. CIDR counts how many leading bits are the network:

| Netmask | CIDR | Binary |
|---|---|---|
| `255.0.0.0` | `/8` | `11111111.00000000.00000000.00000000` |
| `255.255.0.0` | `/16` | `11111111.11111111.00000000.00000000` |
| `255.255.255.0` | `/24` | `11111111.11111111.11111111.00000000` |

With `192.168.1.0/24`, the first three octets are the network and the last octet identifies the host, so `192.168.1.2` and `192.168.1.200` are on the same network and talk directly, while anything outside goes through the router.

Each octet is just an 8-bit binary number. Add the bit values that are set to convert to decimal:

```
128  64  32  16   8   4   2   1
  1   1   0   0    0   0   0   0   = 192
```

#### Network and broadcast address

Given an IP and a netmask you can find two special addresses. The **network address** is the IP with all host bits set to 0 (a logical AND with the mask); the **broadcast address** is all host bits set to 1. The tool `ipcalc` does this for you:

```
IP:        11000000.10101000.00000100.00001100 (192.168.4.12)
Netmask:   11111111.11111111.11111111.00000000 (255.255.255.0, /24)
Network:   11000000.10101000.00000100.00000000 (192.168.4.0)
Broadcast: 11000000.10101000.00000100.11111111 (192.168.4.255)
```

### Communication protocols

Three protocols carry (or check) traffic in different ways.

- **TCP** (Transmission Control Protocol) is reliable and connection-based. Both sides confirm every part, retransmitting anything lost, so the receiver gets exactly what was sent. It is right for a file download or a web page, where correctness matters more than a small delay.
- **UDP** (User Datagram Protocol) is fast and connectionless. The sender just sends, without waiting for confirmation, so some packets can be lost. That is fine for a live video call, game, or stream, where fresh data matters more than replaying an old missing packet.
- **ICMP** (Internet Control Message Protocol) carries no user data. It is used to check connectivity, most visibly by `ping`, which asks "are you there?" and waits for the reply:

```
$ ping google.com
64 bytes from 173.194.32.135: icmp_seq=1 ttl=48 time=239 ms
64 bytes from 173.194.32.135: icmp_seq=2 ttl=48 time=236 ms
--- google.com ping statistics ---
2 packets transmitted, 2 received, 0% packet loss
```

### Ports

An IP address finds the machine; a **port** picks the program on it. A port is a number a program listens on, so `5.1.23.1:80` reaches the web server while `:21` reaches the FTP server on the same host. The default ports every admin should know:

| Port | Service | Port | Service |
|---|---|---|---|
| 20, 21 | FTP (data, control) | 161, 162 | SNMP |
| 22 | SSH | 389 | LDAP |
| 23 | Telnet | 443 | HTTPS |
| 25 | SMTP | 465 | SMTPS |
| 53 | DNS | 514 | syslog |
| 80 | HTTP | 636 | LDAPS |
| 110 | POP3 | 993 | IMAPS |
| 123 | NTP | 995 | POP3S |
| 139 | NetBIOS | | |
| 143 | IMAP | | |

A handy pattern: the secure versions (443, 465, 636, 993, 995) sit above the plain ones and end in "S". The full list of names to numbers is in the file `/etc/services`.

### IPv6

Because IPv4 has only ~4.3 billion addresses, and phones, cars, and fridges all want to be online (the Internet of Things), the long-term fix is **IPv6**. An IPv6 address is 128 bits, written as eight groups of four hex digits:

```
2001:0db8:0a0b:12f0:0000:0000:0000:0001
```

Leading zeros in a group can be dropped, and one run of all-zero groups can be shortened to `::`, so that address becomes:

```
2001:db8:a0b:12f0::1
```

IPv6 provides around 3.4 x 10^38 addresses, effectively limitless for anything we can imagine.

### Summary

IP gives each host a unique address: IPv4 as four 0-255 octets (about 4.3 billion total), IPv6 as 128 bits in eight hex groups, shortened with `::`, giving a practically endless supply. Home devices use the private ranges (`10/8`, `172.16-31`, `192.168/16`) and reach the Internet through a NAT device sharing one public address. Subnetting splits an address into network and host parts, written as a netmask (`255.255.255.0`) or CIDR (`/24`), and from an IP and mask I can find the network (host bits 0) and broadcast (host bits 1) addresses. For transport I know TCP (reliable, confirmed), UDP (fast, best-effort), and ICMP (no data, used by `ping`). A port selects the program, I remember the common ones (22 SSH, 25 SMTP, 53 DNS, 80/443 HTTP/S, and the rest), and `/etc/services` maps every name to its number.
