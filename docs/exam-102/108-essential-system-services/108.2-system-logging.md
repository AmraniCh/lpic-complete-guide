# 108.2 System logging

**Weight: 4**

Candidates should be able to configure rsyslog. This objective also includes configuring the logging daemon to send log output to a central log server or accept log output as a central log server. Use of the systemd journal subsystem is covered. Also, awareness of syslog and syslog-ng as alternative logging systems is included.

**Objectives**

- Basic configuration of rsyslog.
- Understanding of standard facilities, priorities and actions.
- Query the systemd journal.
- Filter systemd journal data by criteria such as date, service or priority
- Configure persistent systemd journal storage and journal size
- Delete old systemd journal data
- Retrieve systemd journal data from a rescue system or file system copy
- Understand interaction of rsyslog with systemd-journald
- Configuration of logrotate.
- Awareness of syslog and syslog-ng.

**Terms**

`/etc/rsyslog.conf`, `/var/log/`, `logger`, `logrotate`, `/etc/logrotate.conf`, `/etc/logrotate.d/`, `journalctl`, `systemd-cat`, `/etc/systemd/journald.conf`, `/var/log/journal/`

### Two logging systems side by side

Most systems run both:

- **systemd-journald** collects logs into a binary journal, queried with `journalctl`.
- **rsyslog** writes traditional plain text files under `/var/log/`.

They cooperate: journald receives messages and passes them to rsyslog, which sorts them into files like `/var/log/syslog` and `/var/log/auth.log`.

```
  services, kernel, apps
          |
   systemd-journald  --->  binary journal  (journalctl)
          |
       rsyslog       --->  /var/log/*.log  (text files)
```

### rsyslog: facilities, priorities and actions

rsyslog decides where a message goes using two labels and an action.

- **Facility**: who sent it (`auth`, `cron`, `kern`, `mail`, `daemon`, `user`, `local0`-`local7`).
- **Priority**: how serious, from low to high (`debug`, `info`, `notice`, `warning`, `err`, `crit`, `alert`, `emerg`).
- **Action**: usually a file to write to.

Rules live in `/etc/rsyslog.conf` and files under `/etc/rsyslog.d/`, written as `facility.priority   action`:

```
# /etc/rsyslog.conf
auth,authpriv.*      /var/log/auth.log
mail.*               -/var/log/mail.log
cron.*               /var/log/cron.log
*.emerg              :omusrmsg:*
kern.warning         /var/log/kern-warn.log
```

A priority matches that level **and above**, so `cron.*` catches everything and `mail.err` would catch `err`, `crit` and up. After editing, restart the service with `systemctl restart rsyslog`.

### logger: send your own message

`logger` writes a line into the log system, useful for testing rules and for scripts:

```
$ logger -p auth.warning "test message from script"
$ tail -1 /var/log/auth.log
Sep  7 14:40:00 host jadi: test message from script
```

### Central log server

rsyslog can send logs to another host or receive them. On the client, forward with `@` (UDP) or `@@` (TCP):

```
# client: send everything to the log server
*.*   @@192.168.1.10:514
```

On the server you enable the matching input module (`imudp` or `imtcp`) so it listens on port 514. This gives one place to read logs from many machines.

### The systemd journal

`journalctl` reads the binary journal. Common queries:

```
$ journalctl                       # everything, oldest first
$ journalctl -e                    # jump to the end
$ journalctl -f                    # follow new lines, like tail -f
$ journalctl -u ssh                # only the ssh service
$ journalctl -b                    # only this boot
$ journalctl -p err                # priority err and above
$ journalctl --since "2026-09-07 09:00" --until "10:00"
$ journalctl -k                    # kernel messages only
```

You can combine filters, for example `journalctl -u nginx -p warning --since today`.

### Persistent journal and its size

By default the journal may live in `/run` and vanish on reboot. To keep it, create the directory and set storage in `/etc/systemd/journald.conf`:

```
$ mkdir -p /var/log/journal
```

```
# /etc/systemd/journald.conf
[Journal]
Storage=persistent
SystemMaxUse=500M
```

Then `systemctl restart systemd-journald`. `SystemMaxUse` caps the total size. To trim old data by hand:

```
$ journalctl --vacuum-time=2weeks    # drop entries older than 2 weeks
$ journalctl --vacuum-size=200M      # shrink to 200M
```

### Reading a journal from another system

Because the journal is just files under `/var/log/journal/`, you can read a copy from a broken machine. Point `journalctl` at the directory or the mounted disk:

```
$ journalctl --directory=/mnt/broken/var/log/journal
$ journalctl --file=/mnt/broken/var/log/journal/*/system.journal
```

`systemd-cat` runs a command and sends its output straight into the journal:

```
$ systemd-cat -t backup /usr/local/bin/backup.sh
```

### logrotate

Logs grow forever unless rotated. `logrotate` renames, compresses and deletes old logs, driven by `/etc/logrotate.conf` and per-package files in `/etc/logrotate.d/`.

```
# /etc/logrotate.d/myapp
/var/log/myapp/*.log {
    weekly
    rotate 4
    compress
    missingok
    notifempty
    create 0640 root adm
}
```

This keeps four weekly files, compressed, and recreates an empty log after rotating. A daily cron or systemd timer runs `logrotate` automatically; test a config with `logrotate -d` (debug, no changes).

### Awareness of alternatives

**syslog** is the original protocol and daemon. **syslog-ng** is a more powerful drop-in alternative to rsyslog with richer filtering. For LPIC-1 you only need to know they exist as alternatives.

### Summary

I remember that journald and rsyslog run together: journald keeps a binary journal I read with `journalctl`, and it hands messages to rsyslog which files them as text under `/var/log/`. rsyslog rules in `/etc/rsyslog.conf` are `facility.priority action`, where a priority means that level and above, and `logger` lets me inject a test line. To centralize, a client forwards with `@` or `@@` to a server listening on port 514. On the journal side I filter with `journalctl` using `-u`, `-b`, `-p` and `--since`, make it survive reboots by creating `/var/log/journal/` and setting `Storage=persistent` in `journald.conf`, cap it with `SystemMaxUse`, and prune with `--vacuum-time`; I can even read a copy from a dead machine with `--directory`. Finally `logrotate`, configured in `/etc/logrotate.d/`, keeps files from growing forever, and I know syslog and syslog-ng exist as alternatives.
