# 108.3 Mail Transfer Agent (MTA) basics

**Weight: 3**

Candidates should be aware of the commonly available MTA programs and be able to perform basic forward and alias configuration on a client host. Other configuration files are not covered.

**Objectives**

- Create e-mail aliases.
- Configure e-mail forwarding.
- Knowledge of commonly available MTA programs (postfix, sendmail, exim) (no configuration)

**Terms**

`~/.forward`, sendmail emulation layer commands, `newaliases`, `mail`, `mailq`, `postfix`, `sendmail`, `exim`

### What an MTA does

A **Mail Transfer Agent** is the program that accepts and delivers email between machines using SMTP. This objective is about basic client tasks only, forwarding and aliases, not about configuring a mail server.

```
   sender  --SMTP-->  MTA  --SMTP-->  MTA  ---->  mailbox
                    (relay)         (delivery)
```

### Commonly available MTAs

You should recognize the three main programs. You do not configure them here.

- **sendmail**: the original UNIX MTA, powerful but famously hard to configure.
- **postfix**: a modern, secure and popular replacement, the common default today.
- **exim**: flexible and configurable, the default on Debian.

The key point is that they all provide the same `sendmail` command interface, so scripts and tools work with any of them. This is the **sendmail emulation layer**: postfix and exim ship a `sendmail` command that behaves like the original.

### System aliases

An **alias** redirects mail for a local name to somewhere else. System aliases live in `/etc/aliases`, one per line as `name: destination`:

```
# /etc/aliases
postmaster: root
root:       jadi
webmaster:  jadi, alice
backups:    /var/log/backups.mail
```

A destination can be another user, a list of users, or a file. After editing, you must rebuild the binary index or the change is ignored:

```
$ newaliases
```

Now mail to `root` reaches `jadi`, and mail to `webmaster` reaches both `jadi` and `alice`. Redirecting `root`'s mail to a real person is a very common first task, so system warnings are actually read.

### User forwarding with ~/.forward

A user who cannot edit `/etc/aliases` can still redirect their own mail with a `~/.forward` file in their home directory. It holds the destination:

```
$ echo "alice@example.com" > ~/.forward
```

To keep a local copy **and** forward, list both, using a backslash before the local username so it does not loop:

```
$ cat ~/.forward
\jadi
alice@example.com
```

### Checking the mail queue

Mail that cannot be delivered right away waits in a queue. `mailq` lists it (this is itself part of the sendmail emulation):

```
$ mailq
Mail queue is empty
```

The `mail` command sends and reads mail from the command line, handy for testing:

```
$ echo "test body" | mail -s "test subject" root
```

### Summary

I keep this at the client level. An MTA moves mail over SMTP, and the three I should know are sendmail (the hard-to-configure original), postfix (the modern default) and exim (Debian's default); they all offer the same `sendmail` command, the emulation layer, so tools do not care which is installed. System-wide redirection is done in `/etc/aliases` as `name: destination`, and I must run `newaliases` afterward for it to take effect, which is how I point `root`'s mail at a real person. A user redirects their own mail with a `~/.forward` file, and can keep a local copy by listing `\username` alongside the outside address. I check pending mail with `mailq` and test delivery with `mail`.
