# 108.3 Mail Transfer Agent (MTA) basics

**Weight: 3**

Candidates should be aware of the commonly available MTA programs and be able to perform basic forward and alias configuration on a client host. Other configuration files are not covered.

**Objectives**

- Create e-mail aliases.
- Configure e-mail forwarding.
- Knowledge of commonly available MTA programs (postfix, sendmail, exim) (no configuration)

**Terms**

`~/.forward`, sendmail emulation layer commands, `newaliases`, `mail`, `mailq`, `postfix`, `sendmail`, `exim`

### Mail Transfer Agents

E-mail is built into Unix systems: every user has a mailbox and can send mail to other local users, or out over the network. The program that carries the mail is a **Mail Transfer Agent (MTA)**. It receives and dispatches messages, both locally and across the network. This objective is only about awareness of the programs plus basic alias and forward setup, not full configuration.

- **sendmail**: one of the oldest MTAs. Powerful but large, hard to configure, and not built with security first, so few systems use it as the default today.
- **exim**: a flexible, feature-rich mailer with strong control over incoming mail through ACLs and authentication. The default on Debian.
- **postfix**: a modern replacement for sendmail with clear configuration files, multiple-domain and encryption support. The most common default MTA.

Most desktop distributions do not install an MTA by default. To experiment, install `postfix` plus a client such as `mailx` (or `bsd-mailx`).

### The sendmail emulation layer

Because sendmail came first, the other MTAs stay backward compatible with it by providing a **sendmail emulation layer**: the same command names and behaviour. That is why `sendmail`, `newaliases`, and `mailq` all work the same way no matter which MTA is actually installed, so what you learn here applies across postfix, exim, and sendmail.

### Aliases

System-wide aliases live in `/etc/aliases`. Each line redirects mail for one name to another user or address:

```
$ cat /etc/aliases
mailer-daemon:  postmaster
postmaster:     root
bin:            root
daemon:         root
news:           root
www:            webmaster
webmaster:      root
```

So mail sent to `news` goes to `root`, and mail to `www` goes to `webmaster` (then on to `root`). After editing this file you must run `newaliases` to rebuild the alias database, or the change is ignored:

```
# newaliases
```

### Sending and reading mail

The `mail` command sends a message from the command line. Type the subject and body, end with a `.` or Ctrl+D:

```
$ mail news
Subject: Email to news user
this will go to root, and by alias on to jadi
.
Cc:
```

Run `mail` with no arguments to read your own mailbox (`/var/mail/<user>`). Inside, type a message number to open it, `d` to delete, and `q` to quit:

```
$ mail
"/var/mail/jadi": 12 messages 12 new
>N  1 root@funlife    apt-listchanges: news
 N 12 jadi@funlife    Email to news user
& 12          # read message 12
& d           # delete the current message
& q           # quit
```

### Forwarding with ~/.forward

`/etc/aliases` is only writable by root. A normal user forwards their own mail by creating a `~/.forward` file in their home directory: every message for that user is sent on to whatever it names. It can hold a local username or a full external address:

```
$ cat ~/.forward
jadi@gmail.com
```

You can also send mail straight from a script by piping the body to `mail`:

```
$ echo "email content" | mail -s "email subject" root
```

### The mail queue

`mailq` lists messages still waiting to be delivered. Each entry shows the queue id, size, arrival time, sender, and the recipients not yet delivered, and if the last attempt failed, the reason:

```
$ mailq
-Queue ID- --Size-- ----Arrival Time---- -Sender/Recipient-------
AA52C228E6B      468 Thu Jan  7 19:59:41  jadi@funlife
(connect to alt2.gmail-smtp-in.l.google.com:25: Network is unreachable)
                                         jadi@gmail.com
-- 0 Kbytes in 1 Request.
```

This is how an admin checks stuck mail. `mailq` is one of the emulation-layer commands, so it works under any MTA.

### Summary

I only need the basics here. Mail is carried by an MTA, and I know the three common ones: `sendmail` (old, hard to configure), `exim` (flexible, Debian's default), and `postfix` (modern and the usual default). They all offer a sendmail emulation layer, so `sendmail`, `newaliases`, and `mailq` behave the same everywhere. System aliases go in `/etc/aliases` (run `newaliases` after editing) to redirect mail for one name to another, while a normal user forwards their own mail with a `~/.forward` file holding a local or external address. I send and read mail with the `mail` command, pipe a body into `mail -s` from scripts, and check undelivered messages with `mailq`.
