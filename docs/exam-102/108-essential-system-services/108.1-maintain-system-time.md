# 108.1 Maintain system time

**Weight: 3**

Candidates should be able to properly maintain the system time and synchronize the clock via NTP.

**Objectives**

- Set the system date and time.
- Set the hardware clock to the correct time in UTC.
- Configure the correct timezone.
- Basic NTP configuration using ntpd and chrony.
- Knowledge of using the pool.ntp.org service.
- Awareness of the ntpq command.

**Terms**

`/usr/share/zoneinfo/`, `/etc/timezone`, `/etc/localtime`, `/etc/ntp.conf`, `/etc/chrony.conf`, `date`, `hwclock`, `ntpd`, `ntpdate`, `chronyc`, `pool.ntp.org`

### How a computer keeps time

There are two clocks. The **hardware clock** (also called the RTC) sits on the motherboard with its own battery and keeps time even when the machine is off. At boot the OS reads it once to set the **system (software) clock**, and from then on uses the system clock while running.

`date` shows and sets the system clock; `hwclock` shows and sets the hardware clock. They are independent, so changing one does not change the other:

```
$ date
Fri Jun 23 01:47:22 PM +0330 2023
$ date -u                                 # the same moment in UTC
$ date +%s                                # Unix epoch: seconds since 1 Jan 1970
$ sudo date -s "Jan 22 22:22:22 2022"     # move the system clock
Sat Jan 22 10:22:22 PM +0330 2022
$ sudo hwclock                            # hardware clock is unchanged
2023-06-23 13:47:41 +03:30
```

The hardware clock can be kept in **UTC** (recommended) or in **local time**. `hwclock` always prints local time, adding your timezone. Common uses:

```
# hwclock -w         # (--systohc) set the hardware clock FROM the system clock
# hwclock -s         # (--hctosys) set the system clock FROM the hardware clock
# hwclock -u -w      # write it, and record that the hardware clock is in UTC
# hwclock --set --date "2024-01-22 22:22:22"   # set the hardware clock to a given time
```

Whether the hardware clock is UTC or local is recorded in `/etc/adjtime`; if that file is missing, UTC is assumed. After you set the system time by hand, run `hwclock -w` so the hardware clock keeps the new time across reboots. (`timedatectl`, seen in 107.3, does the same jobs on systemd, and `timedatectl set-ntp true` enables synchronization.)

### Timezones

Two files matter, both covered in 107.3. `/etc/timezone` is a plain-text name a program can read:

```
$ cat /etc/timezone
Asia/Tehran
```

`/etc/localtime` is the binary timezone data the system actually uses, normally a symlink into `/usr/share/zoneinfo/` so an upgrade keeps it current:

```
$ ls -l /etc/localtime
lrwxrwxrwx 1 root root 31 Jun 22 11:19 /etc/localtime -> /usr/share/zoneinfo/Asia/Tehran
# ln -sf /usr/share/zoneinfo/Asia/Tokyo /etc/localtime   # set it by hand
```

### NTP

The **Network Time Protocol** (UDP port 123) keeps a machine's clock accurate by syncing it against time servers that trace back to atomic clocks. Servers are ranked by **stratum**: stratum 0 is the reference clock itself, stratum 1 is directly attached to one, and each extra hop away counts up. The best-known source is **pool.ntp.org**, which is not one server but a large pool: point a client at it and it is redirected to one of many public servers.

Three implementations are common: `systemd-timesyncd` is a light, client-only syncer built into systemd (turned on with `timedatectl set-ntp true`); `ntpd` is the full daemon that can also serve time to other machines; and `chrony` is the modern alternative. Run only one at a time.

#### ntpdate

`ntpdate` sets the clock once, right now. Follow it with `hwclock -w` so the hardware clock keeps the corrected time:

```
$ sudo ntpdate pool.ntp.org
23 Jun 14:49:55 ntpdate[160138]: adjust time server 31.214.170.254 offset +0.020196 sec
$ sudo hwclock -w
```

#### ntpd

Rather than correcting by hand, run the `ntp` service (`ntpd`) to keep the clock synced continuously. Its config is `/etc/ntp.conf`, where `pool` or `server` lines name the sources:

```
# /etc/ntp.conf
driftfile /var/lib/ntp/ntp.drift
pool 0.debian.pool.ntp.org iburst
pool 1.debian.pool.ntp.org iburst
```

```
# apt install ntp
# systemctl start ntp
```

`ntpd` and `ntpdate` cannot run at the same time, because the daemon already holds the NTP port:

```
# ntpdate pool.ntp.org
the NTP socket is in use, exiting
```

#### ntpq

`ntpq` queries a running `ntpd`. The famous switch is `-p` (print peers):

```
$ ntpq -p
     remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
+46.209.14.1     192.168.5.2      4 u    7   64    1   58.300  -15.546  14.519
*194.225.150.25  194.190.168.1    2 u    5   64    1   31.478   -3.870  95.635
-ntp.tums.ac.ir  195.161.115.4    4 u    4   64    1   30.636    2.485   4.025
```

In the first column, `*` marks the server currently used as the reference, `+` is a good candidate, and `-` is out of range and ignored.

### chrony

**chrony** is a newer NTP implementation. It handles awkward conditions better than `ntpd`, such as laptops with intermittent networks or congested links, and is the default NTP client on Red Hat 8, SUSE 15, and others. Its config is `/etc/chrony.conf` (often `/etc/chrony/chrony.conf`), again with `pool`/`server` lines and a `driftfile`.

`chronyc` is its command-line tool. Pass a command to run it, or start it interactively:

```
$ chronyc tracking          # how well the clock is synced
Reference ID    : 0FED61D6 (paris.time.system76.com)
Stratum         : 3
System time     : 0.001574947 seconds slow of NTP time
Leap status     : Normal
$ chronyc sources           # the servers in use, with * for the selected one
$ sudo chronyc makestep      # jump the clock to the correct time now
```

`chronyc` talks to the service over a socket, so a local `chronyc` can even monitor a remote `chronyd`, limited to read-only commands for safety.

### Summary

I keep two clocks straight: the hardware clock on the motherboard, read once at boot, and the running system clock. `date` sets the system clock and `hwclock` the hardware one; they are separate, so after setting the time by hand I run `hwclock -w`, and I keep the hardware clock in UTC (recorded in `/etc/adjtime`). The timezone comes from `/etc/localtime`, a symlink into `/usr/share/zoneinfo/`, with the plain name in `/etc/timezone`. To stay accurate automatically I use NTP against `pool.ntp.org`: `ntpdate` for a one-shot correction, or the `ntpd` service configured in `/etc/ntp.conf` and inspected with `ntpq -p` (where `*` is the chosen server). The modern alternative is `chrony`, configured in `/etc/chrony.conf` and driven by `chronyc` (`tracking`, `sources`, `makestep`), which copes better with laptops and flaky networks.
