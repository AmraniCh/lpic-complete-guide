# 108.1 Maintain system time

Candidates should be able to properly maintain the system time and synchronize the clock via NTP.

**Objectives**

- Set the system date and time.
- Set the hardware clock to the correct time in UTC.
- Configure the correct timezone.
- Basic NTP configuration using ntpd and chrony.
- Knowledge of using the pool.ntp.org service.
- Awareness of the ntpq command.

**Terms**

`/usr/share/zoneinfo/`, `/etc/timezone`, `/etc/localtime`, `/etc/ntp.conf`, `/etc/chrony.conf`, `date`, `hwclock`, `timedatectl`, `ntpd`, `ntpdate`, `chronyc`, `pool.ntp.org`

### Two clocks

A Linux machine has two clocks:

- The **hardware clock** (also called the RTC or CMOS clock) runs on the motherboard battery, even when the machine is off.
- The **system clock** is kept by the kernel while the machine is running.

```
   power off                power on
  +-----------+   boot     +--------------+   shutdown
  | hardware  | --------> | system clock  | ---------> hardware clock
  | clock     |  reads    | (kernel time) |  can write updated
  +-----------+           +--------------+
```

Best practice is to keep the hardware clock in **UTC** and let the timezone turn it into local time. That avoids problems when clocks shift for daylight saving.

### date: read and set the system clock

```
$ date
Mon Sep  7 14:30:00 CEST 2026
$ date +%Y-%m-%d
2026-09-07
$ date -s "2026-09-07 14:35:00"    # set the clock (needs root)
```

`date` with a `+format` prints just the parts you ask for, which is handy in scripts and log names.

### hwclock: the hardware clock

```
$ hwclock                     # show the hardware clock
2026-09-07 14:30:05.123456+02:00
$ hwclock --systohc           # copy system clock -> hardware clock
$ hwclock --hctosys           # copy hardware clock -> system clock
```

`--systohc` ("system to hardware clock") is what you run after setting the time by hand, so the change survives a reboot.

### Timezone

The timezone comes from `/etc/localtime`, a link into `/usr/share/zoneinfo/`. Set it cleanly with `timedatectl`:

```
$ timedatectl set-timezone Europe/Paris
```

### timedatectl: the modern front end

On systemd machines, `timedatectl` shows and controls both clocks and network sync in one place:

```
$ timedatectl
               Local time: Mon 2026-09-07 14:30:00 CEST
           Universal time: Mon 2026-09-07 12:30:00 UTC
                RTC time: Mon 2026-09-07 12:30:00
                Time zone: Europe/Paris (CEST, +0200)
System clock synchronized: yes
              NTP service: active
$ timedatectl set-ntp true     # turn on automatic network sync
```

### NTP: keeping time in sync over the network

The **Network Time Protocol** corrects the clock against accurate servers on the internet. `pool.ntp.org` is a shared pool of volunteer servers; you point your machine at names like `0.pool.ntp.org` and get a nearby one.

There are two common implementations.

**chrony** is the modern default on most distributions. Its config is `/etc/chrony.conf`:

```
# /etc/chrony.conf
pool 2.pool.ntp.org iburst
driftfile /var/lib/chrony/drift
```

You query it with `chronyc`:

```
$ chronyc sources
MS Name/IP address     Stratum Poll Reach LastRx Last sample
^* ntp1.example.net           2   6   377    17   +12us[+18us]
$ chronyc tracking             # how far off and how fast we drift
```

**ntpd** is the older daemon. Its config is `/etc/ntp.conf`:

```
# /etc/ntp.conf
server 0.pool.ntp.org iburst
server 1.pool.ntp.org iburst
```

You inspect it with `ntpq`:

```
$ ntpq -p
     remote           refid      st t when poll reach   delay   offset  jitter
*ntp1.example.net .GPS.          1 u   42   64  377   10.253   -0.121   0.045
```

`ntpdate` is a one-shot tool that sets the clock once from a server, often used at boot before the daemon starts. A daemon (chrony or ntpd) is what keeps it right over time.

### Summary

I keep in mind two clocks: the battery backed hardware clock and the kernel's system clock, and I store the hardware clock in UTC so daylight saving does not confuse it. By hand I read and set the system clock with `date`, then run `hwclock --systohc` so the change sticks across a reboot. The timezone lives in `/etc/localtime` linked from `/usr/share/zoneinfo/`, and I set it with `timedatectl set-timezone`. Rather than setting time by hand I prefer network sync: I point the machine at `pool.ntp.org` and run a daemon, usually chrony configured in `/etc/chrony.conf` and queried with `chronyc sources` and `chronyc tracking`, or the older ntpd in `/etc/ntp.conf` checked with `ntpq -p`. `ntpdate` sets the clock once, and on systemd I can simply run `timedatectl set-ntp true`.
