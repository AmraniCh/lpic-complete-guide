# 108.4 Manage printers and printing

**Weight: 2**

Candidates should be able to manage print queues and user print jobs using CUPS and the LPD compatibility interface.

**Objectives**

- Basic CUPS configuration (for local and remote printers).
- Manage user print queues.
- Troubleshoot general printing problems.
- Add and remove jobs from configured printer queues.

**Terms**

CUPS configuration files, tools and utilities, `/etc/cups/`, lpd legacy interface (`lpr`, `lprm`, `lpq`)

### CUPS

**CUPS** (the Common UNIX Printing System) is the standard printing service on Linux. A program sends a job to CUPS, CUPS holds it in a per-printer queue, converts it to the printer's language, and sends it to the device.

```
  application --> CUPS queue --> filter/convert --> printer
                     ^
                     |
              you inspect and control
              the queue with lp*/cups* tools
```

CUPS also has a web interface at `http://localhost:631`, where you can add printers and watch queues in a browser.

### Configuration files

CUPS configuration lives in `/etc/cups/`:

- `cupsd.conf`: the daemon's settings (access control, listening address).
- `printers.conf`: the defined printers and their options.
- `ppd/`: the PPD files that describe each printer's capabilities.

After editing files by hand, restart the service with `systemctl restart cups`.

### Managing printers and queues

CUPS provides its own commands:

```
$ lpstat -p -d           # list printers and the default
printer Office_LJ is idle.  enabled since Mon 07 Sep 2026
system default destination: Office_LJ
$ lpstat -a              # show whether each queue accepts jobs
```

Control a queue with these pairs:

```
$ cupsaccept Office_LJ    # queue accepts new jobs
$ cupsreject Office_LJ    # queue rejects new jobs
$ cupsenable Office_LJ    # printer processes the queue
$ cupsdisable Office_LJ   # printer stops printing (jobs still queue)
```

The difference matters when troubleshooting: a disabled printer still collects jobs, a rejecting queue turns them away.

### Printing and the LPD compatibility interface

CUPS understands the older LPD commands, so scripts written years ago still work.

```
$ lpr -P Office_LJ report.pdf     # send a file to a printer
$ lpq -P Office_LJ                # show that queue
Office_LJ is ready and printing
Rank    Owner   Job     File(s)      Total Size
active  jadi    42      report.pdf   40960 bytes
$ lprm 42                          # remove job 42
```

The modern equivalents are `lp` to print and `cancel` to remove a job. Both sets do the same work.

### Troubleshooting

A quick checklist when nothing prints:

- Is the printer enabled and accepting? Check `lpstat -p -d` and `lpstat -a`.
- Are jobs stuck in the queue? Look with `lpq`, clear a bad one with `lprm`.
- Is the daemon running? `systemctl status cups`.
- Look at the CUPS logs in `/var/log/cups/error_log`.

### Summary

I think of CUPS as the print service that queues jobs, converts them and sends them to the device, configured from `/etc/cups/` and reachable in a browser at port 631. I list printers and the default with `lpstat -p -d`, and I control a queue with two pairs of commands: `cupsaccept`/`cupsreject` decide whether the queue takes new jobs, and `cupsenable`/`cupsdisable` decide whether the printer actually prints, a distinction I lean on when debugging. For the jobs themselves I use the LPD compatibility commands `lpr` to print, `lpq` to view, and `lprm` to remove, with `lp` and `cancel` as the modern equivalents. When printing fails I check that the queue is enabled and accepting, look for stuck jobs, confirm the daemon is running, and read `/var/log/cups/error_log`.
