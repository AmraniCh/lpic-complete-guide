# 108.4 Manage printers and printing

**Weight: 2**

Candidates should be able to manage print queues and user print jobs using CUPS and the LPD compatibility interface.

**Objectives**

- Basic CUPS configuration (for local and remote printers).
- Manage user print queues.
- Troubleshoot general printing problems.
- Add and remove jobs from configured printer queues.

**Terms**

CUPS configuration files, tools and utilities, `/etc/cups/`, lpd legacy interface (`lpr`, `lprm`, `lpq`)

### CUPS

Most Linux distributions print through **CUPS**, the Common Unix Printing System. You may need to install it and start its service:

```
$ sudo apt install cups
$ sudo systemctl start cups.service
$ systemctl status cups.service
● cups.service - CUPS Scheduler
     Active: active (running) since Sun 2023-07-16 13:50:20 EDT; 27s ago
   Main PID: 2366 (cupsd)
```

CUPS pulls in many packages because it needs drivers and filters for printers from many vendors. The scheduler daemon is `cupsd`, and it listens on port **631**. You reach it three ways: a web interface, GUI tools in the desktop, and command-line tools.

### Configuration files

Like most programs, CUPS keeps its configuration under `/etc/`, in `/etc/cups/`:

```
# ls /etc/cups/
cupsd.conf  cups-files.conf  ppd/  printers.conf  ssl/  snmp.conf
```

The main file is `cupsd.conf`. It reads much like an Apache config, in plain directives and `<Location>` blocks:

```
# /etc/cups/cupsd.conf
LogLevel warn
Listen localhost:631            # where cupsd accepts connections
Listen /run/cups/cups.sock
Browsing Yes                    # advertise shared printers on the LAN
WebInterface Yes                # enable the web UI
DefaultAuthType Basic

<Location />                    # who may reach the server
  Order allow,deny
</Location>
```

`printers.conf` holds the configured printers and their queues, and the `ppd/` directory holds each printer's PostScript Printer Description (its driver). You do not usually edit these by hand; the web interface writes them for you.

### The web interface

With `WebInterface Yes` set, open `http://localhost:631` (or the server's IP on port 631) in a browser. The important sections:

| Section | Use |
|---|---|
| Administration | add printers, manage jobs, configure the server |
| Jobs | active, pending, and completed jobs |
| Printers | list and search installed printers |

By default any user can view printers and jobs, but changes such as adding a printer need more rights. That is granted at the bottom of `cupsd.conf` with a `<Limit>` block, for example giving members of a `printer_admin` group the right to add, modify, and delete printers:

```
<Limit CUPS-Add-Modify-Printer CUPS-Delete-Printer CUPS-Set-Default>
  AuthType Default
  Require user @printer_admin
  Order deny,allow
</Limit>
```

Adding a printer is usually just picking it from a dropdown, since CUPS ships most common drivers.

### The legacy (LPD) tools

Like the MTAs, CUPS keeps the old BSD/LPD print commands working for compatibility; you may need the `cups-bsd` package. They are the LPD legacy interface named in the objective:

| Command | Use |
|---|---|
| `lpr` | send a file to a printer |
| `lpq` | show the queue and its jobs |
| `lprm` | remove a job from the queue |
| `lpc` | control and troubleshoot printers |

`lpq` lists jobs. `-a` shows all printers, and `-P` picks one (with no space after `-P`, which is the legacy quirk):

```
# lpq -PApple-Dot-Matrix
Apple-Dot-Matrix is ready and printing
Rank    Owner   Job     File(s)               Total Size
active  jadi    1       Untitled Document 1   7168 bytes
1st     jadi    2       Untitled1             2048 bytes
```

`lpr` sends a job, choosing the printer with `-P` (or the default if none is given):

```
$ lpr -PApple-Dot-Matrix for_print.txt
```

`lprm` removes a job by its id; only root can remove another user's job. `lprm -Pprinter -` (a single dash) clears the whole queue:

```
$ lprm 2                      # remove job 2
$ lprm -PApple-Dot-Matrix -   # remove every job on this printer
```

`lpc status` shows the state of a printer:

```
$ lpc status
Apple-Dot-Matrix:
    queuing is enabled
    printing is enabled
    2 entries
```

Two states matter for troubleshooting: **queuing** is whether the queue accepts new jobs at all, and **printing** is whether it actually puts ink on paper (this goes disabled on a paper jam or empty cartridge).

### Controlling the queue

Four commands set those two states, each taking a printer name and an optional `-r` reason:

| Command | Effect |
|---|---|
| `cupsaccept` | the queue accepts new jobs |
| `cupsreject` | the queue rejects new jobs |
| `cupsenable` | actual printing is enabled |
| `cupsdisable` | actual printing is stopped (jobs still queue) |

```
$ cupsdisable Apple-Dot-Matrix -r "need more paper"
$ lpc status
Apple-Dot-Matrix:
    queuing is enabled
    printing is disabled
    2 entries
```

So you can keep collecting jobs while the printer is out of paper (`cupsdisable`), then release them with `cupsenable` once it is refilled. (The System V equivalents `lp`, `lpstat`, and `lpadmin` also work under CUPS if you prefer them.)

### Summary

Printing on Linux is CUPS, the Common Unix Printing System, whose `cupsd` daemon listens on port 631. Its config lives in `/etc/cups/`, chiefly `cupsd.conf` (with `Listen`, `Browsing`, `WebInterface`, and `<Location>`/`<Limit>` access blocks) plus `printers.conf` and the `ppd/` drivers, though I normally configure it through the web interface at `localhost:631`. For the queue I use the LPD legacy commands: `lpr` to print (with `-P`), `lpq` to view the queue, `lprm` to remove a job (or `-P printer -` to clear it), and `lpc status` to check state. Troubleshooting turns on two ideas, queuing (accepting jobs) and printing (ink on paper), which I control with `cupsaccept`/`cupsreject` and `cupsenable`/`cupsdisable`, so I can hold jobs while a printer is jammed and release them later.
