# 106.1 Install and configure X11

Candidates should be able to install and configure X11.

**Objectives**

- Understanding of the X11 architecture.
- Basic understanding and knowledge of the X Window configuration file.
- Overwrite specific aspects of Xorg configuration, such as keyboard layout.
- Understand the components of desktop environments, such as display managers and window managers.
- Manage access to the X server and display applications on remote X servers.
- Awareness of Wayland.

**Terms**

`/etc/X11/xorg.conf`, `/etc/X11/xorg.conf.d/`, `~/.xsession-errors`, `xhost`, `xauth`, `DISPLAY`, `X`

### The X11 architecture

X11 splits the graphics system into two parts that talk over a network protocol.

- The **X server** runs on the machine with the screen, keyboard and mouse. It draws pixels and reads input.
- **X clients** are the applications (a browser, a terminal). They ask the server to draw for them.

The naming feels backwards: the server is the machine in front of you, and the clients can be programs running somewhere else.

```
   +----------------------+          +----------------------+
   |  your machine        |          |  remote machine      |
   |  X server            | <------- |  X client (xterm)    |
   |  (screen, keyboard)  |  X proto |  runs there, draws   |
   +----------------------+          |  on your screen      |
                                     +----------------------+
```

Because of this split, a program on another host can open its window on your display.

### The Xorg configuration file

Modern Xorg autodetects hardware and usually needs no configuration file at all. When you do need one, there are two options:

- A single file, `/etc/X11/xorg.conf`.
- Drop-in snippets in `/etc/X11/xorg.conf.d/`, each ending in `.conf`. This is preferred because you change one small aspect without touching the rest.

A file is made of sections:

```
Section "InputClass"
    Identifier "keyboard-all"
    MatchIsKeyboard "on"
    Option "XkbLayout" "fr"
Option "XkbVariant" "azerty"
EndSection
```

You can generate a starting `xorg.conf` with `Xorg -configure` (or `X -configure`).

### Overriding one aspect, such as keyboard layout

Instead of a full config, drop a small file that changes only what you need. To set a French keyboard for the whole system:

```
# /etc/X11/xorg.conf.d/00-keyboard.conf
Section "InputClass"
    Identifier "system-keyboard"
    MatchIsKeyboard "on"
    Option "XkbLayout" "fr"
EndSection
```

The change takes effect on the next X restart. Errors from a user's session are written to `~/.xsession-errors`, which is the first place to look when a graphical login fails or an app will not start.

### Display managers and window managers

A full graphical desktop is built from layers:

- The **display manager** shows the graphical login screen and starts the session. Examples: `gdm` (GNOME), `sddm` (KDE), `lightdm`.
- The **window manager** draws the title bars and borders and lets you move windows. Examples: Mutter, KWin, Openbox.
- The **desktop environment** bundles a window manager with panels, a file manager and apps. Examples: GNOME, KDE Plasma, Xfce.

### The DISPLAY variable

`DISPLAY` tells a client which X server and screen to draw on. Its form is `host:display.screen`:

```
$ echo $DISPLAY
:0
```

An empty host means the local server. `:0` is the first display, screen 0. If `DISPLAY` is unset or wrong, graphical programs print "cannot open display" and exit.

### Access to the X server and remote display

By default an X server rejects clients from other machines. Two tools manage access:

- `xhost` controls access by host name. `xhost +host` allows a host, `xhost -host` removes it, and a bare `xhost +` allows everyone. Allowing everyone is insecure and only for quick tests.
- `xauth` controls access by a secret token (an MIT-MAGIC-COOKIE) stored in `~/.Xauthority`. This is per user, not per host, so it is safer.

```
$ xhost +192.168.1.50
192.168.1.50 being added to access control list
```

The safe way to run a remote graphical program is SSH X11 forwarding, which tunnels the X protocol and sets `DISPLAY` for you:

```
$ ssh -X user@server
$ xclock          # window appears on your local screen
```

### Wayland

Wayland is the modern replacement for the X11 protocol. The compositor does both drawing and window management in one process, which is simpler and more secure than X11. GNOME and KDE now default to Wayland on many distributions. For LPIC-1 you only need to know it exists and is replacing X.

### Summary

I picture X11 as a client and server that talk over a protocol, where the server is the machine in front of me and the clients are the applications, which is why a remote program can draw on my screen. Xorg mostly configures itself, but when I must intervene I prefer a small drop-in under `/etc/X11/xorg.conf.d/` over a full `/etc/X11/xorg.conf`, for example to force a keyboard layout with `XkbLayout`. A desktop stacks up as a display manager for login, a window manager for the frames, and a desktop environment for the rest. The `DISPLAY` variable points a client at a server and screen, and when things break I read `~/.xsession-errors`. For remote windows I know `xhost` (by host) and `xauth` (by cookie), but in practice I use `ssh -X`, which is both easy and secure. Finally, I am aware that Wayland is the newer protocol steadily replacing X.
