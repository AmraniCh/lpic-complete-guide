# 106.2 Graphical desktops

**Weight: 1**

Candidates should be aware of major Linux desktops. Furthermore, candidates should be aware of protocols used to access remote desktop sessions.

**Objectives**

- Awareness of major desktop environments
- Awareness of protocols to access remote desktop sessions

**Terms**

KDE, Gnome, Xfce, X11, XDMCP, VNC, Spice, RDP

### Desktop environments

When a system boots into graphical mode you get a graphical login screen. That login layer is based on **XDMCP** (X Display Manager Control Protocol), and a display manager such as `GDM` (GNOME), `SDDM` (KDE), or the generic `XDM` handles the theming and the login itself.

After you log in you are in the GUI. A **window manager** is the minimum piece: it draws and manages the windows, and even the most minimal GUI needs one. Add panels, icons, drag and drop, a file manager, a calculator, an e-mail client, and matching libraries, and you have a full **desktop environment**. Some people prefer a bare window manager and add only what they want; others want the complete package.

The three best known desktop environments:

#### GNOME
- Started in 1999.
- Focuses on productivity and accessibility.
- The default on most GNU/Linux distributions.

#### KDE (Plasma)
- Started in 1996; from version 5 (2016) rebranded to KDE Plasma.
- Highly customizable.
- Used at NASA and CERN.

#### Xfce
- Started in 1999.
- Lightweight but still polished.
- Modular.

### Remote connection to GUIs

Often you want a GUI from another machine: to help a friend, to check your desktop from your phone, or to run a heavy graphical program on a stronger remote host. Several protocols do this.

#### X forwarding

Not strictly listed for this objective, but very useful. With an SSH server you can run a graphical program on the remote host and see its window locally. Make sure `X11Forwarding yes` is set in `/etc/ssh/sshd_config` (restart the service if you change it), then:

```
$ ssh -X server.example.net
$ xeyes                       # the window appears on your own machine
```

The same works for a browser or a CPU-hungry simulation.

#### VNC

**VNC** (Virtual Network Computing) is old but still widely used. It is cross-platform and uses the RFB protocol. Its port is `5900` plus the display number, so display 1 listens on `5901`. VNC is flexible with clients everywhere, but on its own it lacks security, so it is usually tunnelled.

#### Spice

**Spice** (Simple Protocol for Independent Computing Environment) became open source when Red Hat bought the company in 2008. It is used to reach KVM virtual machines, with speeds close to a local connection and low CPU use. There is one server and many clients, including GNOME Boxes.

#### RDP

**RDP** (Remote Desktop Protocol) comes from Windows. With a server such as `xrdp` a Linux machine can accept RDP connections on port `3389`. The traffic is encrypted by default, and free RDP clients are plentiful.

### Summary

I need awareness here, not deep configuration. The graphical login is a display manager (`GDM`, `SDDM`, `XDM`) built on `XDMCP`. Above the display server, a window manager draws the window frames, and a desktop environment bundles a window manager with panels and apps; the three big ones are `GNOME` (default most places, productivity and accessibility), `KDE` Plasma (very customizable), and `Xfce` (lightweight). To reach a GUI remotely I know four options: SSH X forwarding with `ssh -X` for single programs over `X11`, `VNC` (RFB, port 5900 plus display, flexible but insecure on its own), `Spice` (fast, aimed at KVM virtual machines), and `RDP` (port 3389, encrypted, via `xrdp`).
