# 110.1 Perform security administration tasks

**Weight: 3**

Candidates should know how to review system configuration to ensure host security in accordance with local security policies.

**Objectives**

- Audit a system to find files with the suid/sgid bit set.
- Set or change user passwords and password aging information.
- Being able to use nmap and netstat to discover open ports on a system.
- Set up limits on user logins, processes and memory usage.
- Determine which users have logged in to the system or are currently logged in.
- Basic sudo configuration and usage.

**Terms**

`find`, `passwd`, `fuser`, `lsof`, `nmap`, `chage`, `netstat`, `sudo`, `/etc/sudoers`, `su`, `usermod`, `ulimit`, `who`, `w`, `last`

### Finding suid and sgid files

A file with the **suid** bit runs as its owner, and one with the **sgid** bit runs as its group, no matter who starts it. That is powerful and sometimes dangerous, so you audit which files carry these bits.

```
$ find / -perm -4000 -type f 2>/dev/null    # suid files
/usr/bin/passwd
/usr/bin/sudo
/usr/bin/su
$ find / -perm -2000 -type f 2>/dev/null    # sgid files
```

`-4000` matches suid, `-2000` matches sgid. The `2>/dev/null` hides permission errors from directories you cannot read. An unexpected suid file, for example a copy of a shell, is a red flag.

### Passwords and aging

`passwd` sets a password, and can lock or unlock an account:

```
$ passwd alice          # set alice's password
$ passwd -l alice       # lock the account
$ passwd -u alice       # unlock it
$ passwd -S alice       # show status
alice P 09/07/2026 0 99999 7 -1
```

`chage` manages the aging fields, so a policy can force regular changes:

```
$ chage -M 90 -W 7 alice   # expire after 90 days, warn 7 days ahead
$ chage -l alice           # show current aging
```

### Discovering open ports

Open ports are the doors into a machine. Check them from two angles.

Locally, `netstat` (or the newer `ss`) lists listening sockets:

```
$ netstat -tlnp
Proto Local Address     State    PID/Program
tcp   0.0.0.0:22        LISTEN   712/sshd
tcp   127.0.0.1:631     LISTEN   690/cupsd
```

From the network, `nmap` scans a host to see which ports answer:

```
$ nmap 192.168.1.20
PORT     STATE  SERVICE
22/tcp   open   ssh
80/tcp   open   http
```

Comparing the two shows whether a service is exposed more widely than you intended. Only scan machines you are allowed to.

### fuser and lsof

When a port or file is in use and you need to know by what, these help:

```
$ fuser 8080/tcp          # which process holds TCP port 8080
8080/tcp:            2481
$ lsof -i :22             # open network files on port 22
$ lsof /var/log/syslog    # who has this file open
```

### Limits on users

**Soft limits** can be raised by the user up to the **hard limit**. `ulimit` shows and sets them for the current shell:

```
$ ulimit -a
$ ulimit -u          # max user processes
$ ulimit -n 4096     # raise open files for this session
```

Permanent, per user limits go in `/etc/security/limits.conf`, which protects a machine from a runaway process or a fork bomb:

```
# /etc/security/limits.conf
alice   hard   nproc   200      # alice: at most 200 processes
*       hard   nofile  8192     # everyone: at most 8192 open files
```

### Who is or was logged in

```
$ who            # who is logged in now
jadi   pts/0   2026-09-07 09:15 (192.168.1.5)
$ w              # logged in users and what they are running
$ last           # history of logins from /var/log/wtmp
jadi   pts/0    192.168.1.5   Mon Sep  7 09:15   still logged in
```

`last` is useful after an incident to see when and from where accounts connected.

### sudo

`sudo` runs a single command as another user, usually `root`, without sharing the root password. It is safer than `su` because it is per command, logged, and controlled by rules.

```
$ sudo systemctl restart nginx
$ sudo -l               # what am I allowed to run
```

Rules live in `/etc/sudoers`, which you must edit with `visudo` (it checks syntax before saving, so a typo cannot lock everyone out):

```
# /etc/sudoers
alice   ALL=(ALL:ALL) ALL                        # full sudo
web     ALL=(root) /usr/bin/systemctl restart nginx  # one command only
%admin  ALL=(ALL) ALL                            # a whole group
```

By contrast, `su -` opens a full shell as another user and needs that user's password.

### Summary

I audit a host along a few lines. For dangerous permissions I run `find / -perm -4000` and `-2000` to list suid and sgid files and spot anything odd. For accounts I set passwords and lock them with `passwd`, and enforce aging with `chage -M`. For exposure I list local listeners with `netstat`/`ss` and scan from outside with `nmap`, comparing the two, and I trace a busy port or file with `fuser` and `lsof`. I cap resource use with `ulimit` now and `/etc/security/limits.conf` permanently to stop runaway processes. I check current and past logins with `who`, `w` and `last`. Finally I prefer `sudo` over `su`: it grants rights per command, is logged, and is configured in `/etc/sudoers` through `visudo`, which validates the file so a mistake cannot lock me out.
