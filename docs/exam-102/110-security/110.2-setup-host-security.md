# 110.2 Setup host security

**Weight: 3**

Candidates should know how to set up a basic level of host security.

**Objectives**

- Awareness of shadow passwords and how they work.
- Turn off network services not in use.
- Understand the role of TCP wrappers.

**Terms**

`/etc/nologin`, `/etc/passwd`, `/etc/shadow`, `/etc/xinetd.d/`, `/etc/xinetd.conf`, `systemd.socket`, `/etc/inittab`, `/etc/init.d/`, `/etc/hosts.allow`, `/etc/hosts.deny`

### Shadow passwords

Long ago, hashed passwords sat in `/etc/passwd`, which every user can read, so anyone could copy the hashes and try to crack them offline. **Shadow passwords** move the hash into `/etc/shadow`, readable only by `root`:

```
$ ls -l /etc/passwd /etc/shadow
-rw-r--r-- 1 root root   /etc/passwd
-rw-r----- 1 root shadow /etc/shadow
```

The password field in `/etc/passwd` is now just an `x`. `/etc/shadow` also holds the aging fields (last change, minimum, maximum, warning). Every modern system uses shadow passwords, and you can confirm or convert with `pwconv`.

### Turning off unused services

Every running service is a possible way in, so the simplest security win is to switch off what you do not need. On systemd, `disable` stops it starting at boot and `stop` stops it now:

```
$ systemctl list-units --type=service --state=running
$ systemctl disable --now cups     # stop now and at boot
$ systemctl mask telnet            # prevent it starting at all
```

To find what is listening, use `ss -tlnp` (from 110.1) and switch off anything you do not recognize.

### Legacy service managers

Older systems started services differently, and you should recognize them:

- **SysV init**: scripts in `/etc/init.d/`, with the default runlevel set in `/etc/inittab`.
- **inetd / xinetd**: a "super server" that listened on many ports and started a service only when a connection arrived. Each service had a file in `/etc/xinetd.d/`, with `disable = yes` to switch it off, and `/etc/xinetd.conf` for global settings.

```
# /etc/xinetd.d/telnet
service telnet {
    disable = yes
}
```

The systemd equivalent of this "start on demand" idea is a **socket unit** (`systemd.socket`): systemd listens on the socket and starts the service on the first connection.

### Blocking logins with /etc/nologin

If the file `/etc/nologin` exists, normal users cannot log in, and its contents are shown as the reason. Only `root` may still log in. This is used during maintenance:

```
$ echo "System down for maintenance until 15:00" > /etc/nologin
```

Delete the file to allow logins again.

### TCP wrappers

**TCP wrappers** are an older host based access control for services linked against `libwrap` (such as `sshd` on some systems and the xinetd services). Two files decide access:

- `/etc/hosts.allow`: who is allowed.
- `/etc/hosts.deny`: who is denied.

`hosts.allow` is checked first, so an allow beats a deny. A common "deny all, then allow some" setup:

```
# /etc/hosts.deny
ALL: ALL

# /etc/hosts.allow
sshd: 192.168.1.0/24
sshd: 10.0.0.5
```

That blocks everything, then lets SSH in only from the local network and one host. TCP wrappers are largely replaced by firewalls today, but you should know the two files and that allow wins over deny.

### Summary

I build basic host security from a few habits. Shadow passwords keep the hashes in `/etc/shadow`, readable only by `root`, so `/etc/passwd` shows only an `x`; this is standard now. The biggest quick win is switching off services I do not use, with `systemctl disable --now` and `mask`, after finding listeners with `ss`. I recognize the older mechanisms too: SysV scripts in `/etc/init.d/` with `/etc/inittab`, and the inetd/xinetd super server whose per service files in `/etc/xinetd.d/` use `disable = yes`, whose modern counterpart is a systemd socket unit. Creating `/etc/nologin` blocks ordinary logins during maintenance. Finally TCP wrappers give host based access through `/etc/hosts.allow` and `/etc/hosts.deny`, where allow is checked first, a pattern I use as deny all then allow a few, keeping in mind firewalls have largely taken over this role.
