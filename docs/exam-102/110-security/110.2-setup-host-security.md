# 110.2 Setup host security

**Weight: 3**

Candidates should know how to set up a basic level of host security.

**Objectives**

- Awareness of shadow passwords and how they work.
- Turn off network services not in use.
- Understand the role of TCP wrappers.

**Terms**

`/etc/nologin`, `/etc/passwd`, `/etc/shadow`, `/etc/xinetd.d/`, `/etc/xinetd.conf`, `systemd.socket`, `/etc/inittab`, `/etc/init.d/`, `/etc/hosts.allow`, `/etc/hosts.deny`

### Shadow passwords

`/etc/passwd` must be readable by everyone, because many programs look up user information there. That is a problem for passwords: if the hash lived in `/etc/passwd`, anyone could read every user's hash and try to crack it. **Shadow passwords** solve this. The password field in `/etc/passwd` is just an `x`, and the real hash lives in `/etc/shadow`, which only root and the `shadow` group can read:

```
$ grep jadi /etc/passwd
jadi:x:1000:1000:jadi:/home/jadi:/bin/bash
$ grep jadi /etc/shadow
grep: /etc/shadow: Permission denied
$ ls -l /etc/passwd /etc/shadow
-rw-r--r-- 1 root root   2.5K Jun  5 19:14 /etc/passwd
-rw-r----- 1 root shadow 1.5K Jun 11 17:36 /etc/shadow
```

So a normal user can still change their own password (through the suid `passwd` program) without ever reading anyone else's hash.

### /etc/nologin and the nologin shell

If the file `/etc/nologin` exists, normal logins are refused and its contents are shown to anyone who tries. It is handy during maintenance: create it to keep users out, delete it to let them back in. Root can still log in.

```
# echo "System down for maintenance until 15:00" > /etc/nologin
```

Separately, there is a dummy shell `/sbin/nologin`. Give it to an account and that user cannot get a shell, though the account stays active for other services such as mail or FTP. This is how service accounts are stopped from logging in:

```
# usermod -s /sbin/nologin baduser
```

### Super-servers

A **super-server** (service dispatcher) is a daemon that listens on behalf of other services and starts each one only when a request arrives. That saves resources and adds a control point, effectively a wrapper around the real service. The classic one is **xinetd**, configured by `/etc/xinetd.conf` and per-service files in `/etc/xinetd.d/`:

```
# /etc/xinetd.d/telnet
service telnet
{
    disable     = no          # yes turns this service off
    server      = /usr/sbin/in.telnetd
    no_access   = 10.0.1.0/24
    access_times = 09:45-16:15
}
```

Set `disable = yes` and restart `xinetd` to switch a service off. Few systems still use xinetd. The modern equivalent is a **systemd.socket** unit: services such as ssh or cups can ship a `.socket` unit alongside the `.service`. Disable the service and enable the socket, and systemd listens on the port and starts the service on demand.

### TCP wrappers: /etc/hosts.allow and /etc/hosts.deny

**TCP wrappers** control which hosts may reach a service, through two files. The logic mirrors `cron.allow`/`cron.deny`: `/etc/hosts.allow` is checked first and is a whitelist, `/etc/hosts.deny` is a blacklist. A service is allowed unless denied, and an allow entry wins:

```
# /etc/hosts.allow
vsftpd: 10.10.100.        # only the 10.10.100.* network may use vsftpd
ALL: LOCAL               # local connections may use anything
```

A service obeys these files only if it was built against the `libwrap` library. You can check:

```
$ ldd /usr/sbin/vsftpd | grep libwrap
    libwrap.so.0 => /lib/x86_64-linux-gnu/libwrap.so.0
```

`ALL` matches every service. Like super-servers, TCP wrappers are largely historical now that services listen for themselves, but the objective still expects you to understand their role.

### Turning off unused services

The best host hardening is to run less. A service that is not needed should be stopped and disabled so it does not start at boot. On systemd:

```
$ systemctl list-units --state active --type service   # what is running
# systemctl disable vsftpd.service --now                # stop now and at boot
```

On older SysV systems, services were scripts in `/etc/init.d/` with links in `/etc/rc*.d/`, listed with `service --status-all`, and disabled with `chkconfig vsftpd off` (Red Hat) or `update-rc.d vsftpd remove` (Debian). The SysV boot behaviour was set in `/etc/inittab`, whose `id:3:initdefault:` line chose the default runlevel (see 101.3).

### Summary

Basic host security is a few habits. Shadow passwords keep hashes out of the world-readable `/etc/passwd` by storing them in root-only `/etc/shadow`, so users change their own password without seeing anyone else's. I block logins during maintenance with `/etc/nologin`, and stop a service account from getting a shell by setting its shell to `/sbin/nologin` with `usermod`. Super-servers such as `xinetd` (files in `/etc/xinetd.d/`) once wrapped services and started them on demand, a role now filled by `systemd.socket` units. TCP wrappers gate access by host through `/etc/hosts.allow` (whitelist, checked first) and `/etc/hosts.deny` (blacklist), for any service linked against `libwrap`. Above all, I turn off what I do not use, disabling services with `systemctl disable --now` (or the old `chkconfig`/`update-rc.d` and `/etc/init.d/`, `/etc/inittab`).
