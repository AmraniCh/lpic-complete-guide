# 107.1 Manage user and group accounts and related system files

**Weight: 5**

Candidates should be able to add, remove, suspend and change user accounts.

**Objectives**

- Add, modify and remove users and groups.
- Manage user/group info in password/group databases.
- Create and manage special purpose and limited accounts.

**Terms**

`/etc/passwd`, `/etc/shadow`, `/etc/group`, `/etc/skel/`, `chage`, `getent`, `groupadd`, `groupdel`, `groupmod`, `passwd`, `useradd`, `userdel`, `usermod`

### /etc/passwd

Every account has one line here, with seven fields separated by colons:

```
jadi:x:1000:1000:Jadi Mirmirani:/home/jadi:/bin/bash
```

```
jadi : x : 1000 : 1000 : Jadi Mirmirani : /home/jadi : /bin/bash
 |     |    |      |         |                |            |
name   |    UID    GID     GECOS (full name)  home         login shell
       password now in /etc/shadow, shown as x
```

The `x` in the password field means the real password lives in `/etc/shadow`. A login shell of `/usr/sbin/nologin` or `/bin/false` means the account cannot log in interactively.

### /etc/shadow

The password file is world readable, so the hashed passwords are kept separately in `/etc/shadow`, which only `root` can read. It has nine fields:

```
jadi:$6$xyz...:19700:0:99999:7:::
```

| Field | Meaning |
|---|---|
| 1 | username |
| 2 | hashed password (`!` or `*` means locked) |
| 3 | days since 1970 of last password change |
| 4 | minimum days before the password can change again |
| 5 | maximum days the password is valid |
| 6 | warning days before expiry |
| 7 | inactive days after expiry before the account is disabled |
| 8 | account expiry date, in days since 1970 |
| 9 | reserved |

### /etc/group

Groups are defined here, one per line, four fields:

```
developers:x:1001:jadi,alice
```

That is group name, password (rarely used, in `/etc/gshadow`), GID, and a comma separated list of **supplementary** members. A user's **primary** group comes from field 4 of `/etc/passwd`, not from this list.

### Adding a user

`useradd` creates the account. The important options:

```
$ useradd -m -s /bin/bash -c "Alice Smith" -G developers alice
```

- `-m` creates the home directory and copies `/etc/skel/` into it.
- `-s` sets the login shell.
- `-c` sets the GECOS comment (full name).
- `-G` adds supplementary groups.

The defaults for `useradd` come from `/etc/default/useradd` and `/etc/login.defs`. The new account has no usable password yet, so set one:

```
$ passwd alice
New password:
Retype new password:
passwd: password updated successfully
```

On Debian systems the friendlier `adduser` script wraps `useradd` and prompts for each value.

### Modifying a user

`usermod` changes an existing account.

```
$ usermod -s /usr/sbin/nologin alice   # change shell
$ usermod -L alice                      # lock (suspend) the account
$ usermod -U alice                      # unlock it
```

To add a user to another group **without** dropping the groups they are already in, always combine `-a` (append) with `-G`:

```
$ usermod -aG sudo alice
```

Forgetting `-a` replaces the whole supplementary group list, a very common mistake.

### Removing a user

```
$ userdel alice        # remove the account, keep the home directory
$ userdel -r alice     # remove the account and its home and mail
```

### Password aging with chage

`chage` reads and sets the aging fields in `/etc/shadow`.

```
$ chage -l alice
Last password change                    : Sep 06, 2026
Password expires                        : never
Password inactive                       : never
Account expires                         : never
Minimum number of days between password change  : 0
Maximum number of days between password change  : 99999
Number of days of warning before password expires : 7
```

To force a password change every 90 days with a 7 day warning:

```
$ chage -M 90 -W 7 alice
```

To force a change at next login, set the last change date to zero:

```
$ chage -d 0 alice
```

### Managing groups

```
$ groupadd developers          # create a group
$ groupmod -n devs developers  # rename it to devs
$ groupdel devs                # delete it
```

You cannot delete a group that is still someone's primary group.

### getent

`getent` queries the system databases through NSS, so it returns accounts from local files **and** from remote sources like LDAP, which `grep /etc/passwd` would miss.

```
$ getent passwd alice
alice:x:1001:1001:Alice Smith:/home/alice:/bin/bash
$ getent group developers
developers:x:1001:alice
```

### Special and limited accounts

System services run under their own accounts so a compromised service does not have full rights. These usually have:

- a UID below 1000 (regular users start at 1000),
- no valid password (`!` in `/etc/shadow`),
- a shell of `/usr/sbin/nologin` or `/bin/false` so nobody can log in as them.

```
$ useradd -r -s /usr/sbin/nologin backupsvc
```

The `-r` flag makes a system account with a low UID and no home directory by default.

### Summary

I treat this objective as three files and a set of tools that edit them. `/etc/passwd` holds the seven public fields per user, `/etc/shadow` holds the hashed password and its aging rules and is readable only by `root`, and `/etc/group` lists groups and their supplementary members. To add someone I use `useradd -m` so `/etc/skel/` is copied in, then set a password with `passwd`; on Debian `adduser` does this interactively. I change accounts with `usermod`, being careful to write `usermod -aG` so I append a group rather than replace the list, and I lock or unlock with `-L` and `-U`. I remove with `userdel`, adding `-r` to take the home directory too. Aging is `chage`: `-M` and `-W` for the policy, `-d 0` to force a change at next login. Groups are managed with `groupadd`, `groupmod` and `groupdel`, and I query everything with `getent` so LDAP accounts show up. For services I create limited accounts with `useradd -r` and a `nologin` shell so they cannot be used to log in.
