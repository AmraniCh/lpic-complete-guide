# 107.1 Manage user and group accounts and related system files

**Weight: 5**

Candidates should be able to add, remove, suspend and change user accounts.

**Objectives**

- Add, modify and remove users and groups.
- Manage user/group info in password/group databases.
- Create and manage special purpose and limited accounts.

**Terms**

`/etc/passwd`, `/etc/shadow`, `/etc/group`, `/etc/skel/`, `chage`, `getent`, `groupadd`, `groupdel`, `groupmod`, `passwd`, `useradd`, `userdel`, `usermod`

### Passwords

Each user changes their own password with `passwd`. It asks for the current password first, to be sure the change is made by the account owner, and it refuses a password that is too short, too similar to the old one, a dictionary word, or equal to the username:

```
$ passwd
Changing password for jadi.
(current) UNIX password:
New password:
Retype new password:
passwd: password updated successfully
```

Root can change any user's password without knowing the old one, and can even force a weak one through the warnings:

```
# passwd jadi
New password:
BAD PASSWORD: it does not contain enough DIFFERENT characters
Retype new password:
passwd: password updated successfully
```

### Users and groups

Linux is multi-user, and managing those users is part of the job: add, remove, and modify them. It also has **groups**. You give a permission to a group and then add users to it, exactly as you saw with `chmod`, where a `cdrom` group can read `/dev/cdrom` and anyone who needs the CD is added to that group.

A user can belong to many groups, but only one is the **primary group**. A file, by contrast, is owned by exactly one group.

### Managing users

#### Adding users

`useradd` creates a user. The main switches:

| Switch | Meaning |
|---|---|
| `-d` | home directory (`-d /home/jadi`) |
| `-m` | create the home directory |
| `-s` | login shell |
| `-G` | add to extra groups |
| `-c` | comment, usually the person's real name (quote it if it has spaces) |

```
# useradd -m -d /home/jadi -s /bin/bash -c "Jadi the geek" -G sudo jadi
```

Some systems create the home directory automatically, others need `-m`, so it is good practice to always pass it. When the home is created, the contents of `/etc/skel/` are copied in as a template. The friendlier `adduser` command (Debian) is interactive and asks for the password, home, and so on.

#### Modifying users

`usermod` changes an existing user and accepts most `useradd` switches, so `usermod -s /bin/csh jadi` changes the login shell. Three extra switches matter:

| Switch | Meaning |
|---|---|
| `-L` | lock the account |
| `-U` | unlock the account |
| `-aG` | append to more groups |

Be careful with groups: `usermod -G wheel,users jadi` makes jadi a member of **only** those two groups, dropping the rest. To *add* a group without removing the others, use append: `usermod -aG wheel jadi`. Think of `-G` as "jadi's groups are..." and `-aG` as "also add jadi to...".

#### Deleting users

`userdel` removes a user:

```
# userdel jadi
```

Add `-r` to also erase the home directory and mail spool.

### Managing groups

Groups work the same way, with `groupadd`, `groupmod`, and `groupdel`. Each group has a name and a numeric id:

```
# groupadd -g 1200 newgroup      # create with id 1200
# groupmod -g 2000 newgroup      # change its id
# groupdel newgroup              # delete it
```

Deleting a group does not delete its members; they simply stop being members. Users and groups created by the admin usually start at id 1000 and count up.

### /etc/passwd

This world-readable file holds one line per user:

```
$ tail -3 /etc/passwd
sshd:x:493:491:SSH daemon:/var/lib/sshd:/bin/false
jadi:x:1000:100:jadi:/home/jadi:/bin/bash
privoxy:x:484:480:Daemon user for privoxy:/var/lib/privoxy:/bin/false
```

The seven colon-separated fields are:

```
username : x : userid : primary-group-id : name/comment : home dir : shell
```

The second field is just `x`. Long ago it held the hashed password, but because this file must be readable by everyone, the password moved to `/etc/shadow`, and the `x` says "look there". Service accounts such as `sshd` get `/bin/false` (or `/usr/sbin/nologin`) as their shell, which stops anyone logging in as them.

### /etc/shadow

This file holds the hashed passwords and is readable only by root and the `shadow` group:

```
# ls -l /etc/passwd /etc/shadow
-rw-r--r-- 1 root root   1.9K Oct 28 15:47 /etc/passwd
-rw-r----- 1 root shadow  851 Oct 29 19:06 /etc/shadow
$ sudo tail -2 /etc/shadow
lightdm:*:16369::::::
jadi:$6$enk5I3bv$uSQr...maz0:19473:0:99999:7:::
```

After the hash come the password-aging fields. For `19473:0:99999:7:::` they mean:

| Field | Meaning |
|---|---|
| `19473` | day of the last password change (days since 1 Jan 1970) |
| `0` | minimum days before the password may be changed again |
| `99999` | maximum days before the password must be changed |
| `7` | days of warning before it expires |

You do not edit these numbers by hand. `chage` does it: `chage jadi` prompts for each field, or use switches such as `-l` (list), `-E` (account expiry date, a date, or `-1` for never), `-M` (max days), and `-W` (warning days):

```
# chage -l jadi
Last password change                : Apr 26, 2023
Password expires                    : never
Maximum number of days between password change : 99999
Number of days of warning before password expires : 7
```

In the second field, `*` or `!` means the account is locked and cannot log in with a password. On Red Hat systems `!!` means the account has never had a password set.

### /etc/group

This file lists groups, their ids, and their extra members:

```
$ tail -3 /etc/group
vboxusers:x:481:
input:x:1000:jadi,joe
privoxy:x:480:
```

The format is `groupname:x:groupid:members`. The `x` is for a group password, which is essentially never used; if set it lives in `/etc/gshadow`.

### Checking user info

`id` shows a user's ids and group memberships:

```
# id jadi
uid=1000(jadi) gid=100(users) groups=1000(input),100(users)
```

`getent` (get entry) queries the system databases, including `passwd`, `group`, `shadow`, and `hosts`, which is handy when accounts come from LDAP rather than the flat files:

```
# getent passwd jadi
jadi:x:1000:100:jadi:/home/jadi:/bin/bash
# getent group input
input:x:1000:jadi,joe
```

### Summary

This objective is the full life cycle of accounts. I set passwords with `passwd` (users need the old one, root does not), and I create accounts with `useradd` (always `-m`, plus `-d`, `-s`, `-G`, `-c`), which seeds the home from `/etc/skel/`. I change accounts with `usermod`, using `-L`/`-U` to lock and unlock and, crucially, `-aG` to add a group without wiping the others, and I remove them with `userdel -r`. Groups use `groupadd`, `groupmod`, and `groupdel`. The data lives in three files: `/etc/passwd` (world-readable, seven fields, `x` pointing at the shadow file, `nologin`/`false` shells for services), `/etc/shadow` (root-only, the hash plus aging fields I manage with `chage`, where `!` means locked), and `/etc/group` (names, ids, members). To inspect an account I use `id` and `getent`.
