# 107.3 Localisation and internationalisation

**Weight: 3**

Candidates should be able to localise a system in a different language than English. As well, an understanding of why LANG=C is useful when scripting.

**Objectives**

- Configure locale settings and environment variables.
- Configure timezone settings and environment variables.

**Terms**

`/etc/timezone`, `/etc/localtime`, `/usr/share/zoneinfo/`, `LC_*`, `LC_ALL`, `LANG`, `TZ`, `/usr/bin/locale`, `tzselect`, `timedatectl`, `date`, `iconv`, UTF-8, ISO-8859, ASCII, Unicode

### Timezones

The world has many timezones and many languages, and this creates a few needs at once: you may want your system in your own language, the machine needs your timezone so it can run scheduled jobs at the right moment, and programs ask the system about your language and keyboard preferences.

Start simple. `date` shows the current date and time, and `+` gives a custom format:

```
$ date
Fri Jun  2 02:07:35 PM EDT 2023
$ date +'%Y%m%d-%H%M'
20230602-1408
```

`timedatectl` shows more, including the timezone and whether the clock is synchronized:

```
# timedatectl
               Local time: Fri 2023-06-02 14:23:34 EDT
           Universal time: Fri 2023-06-02 18:23:34 UTC
                Time zone: America/New_York (EDT, -0400)
System clock synchronized: no
              NTP service: active
```

A timezone is your offset from a reference (UTC). That lets people agree on a moment regardless of location: "start at 02:30 UTC" means the same instant to everyone. Most installers ask for the timezone; later you can change it in a GUI or with the text tool `tzselect`, which walks you through continent and country and then prints a `TZ` value like `Atlantic/Bermuda`.

The `TZ` variable sets the timezone for *you*, not the whole system. Export it in `~/.profile` to keep it, or use it once to check the time elsewhere:

```
$ env TZ='Asia/Tokyo' date
Sat Jun  3 03:25:40 AM JST 2023
```

### Configuring the system timezone

All timezone data lives in `/usr/share/zoneinfo/` as binary files. The system timezone is set by pointing `/etc/localtime` at the right one, ideally as a symbolic link so an upgrade does not overwrite a copied file:

```
# ls -l /etc/localtime
lrwxrwxrwx 1 root root 38 Apr 26 09:41 /etc/localtime -> ../usr/share/zoneinfo/America/New_York
```

On Debian-based systems the zone name is also written in plain text in `/etc/timezone` (for example `America/New_York`). With systemd, `timedatectl set-timezone Asia/Tokyo` updates the link for you.

### Configuring languages (locales)

`locale` (the `/usr/bin/locale` command) shows the current language settings:

```
# locale
LANG=en_US.UTF-8
LC_TIME="en_US.UTF-8"
LC_NUMERIC="en_US.UTF-8"
LC_MONETARY="en_US.UTF-8"
...
LC_ALL=
```

These are environment variables. `LANG` is the default for everything; here `en_US.UTF-8` means English, US variant, UTF-8 encoding. The individual `LC_*` variables override single aspects: set `LC_TIME=en_GB.UTF-8` and only the time format switches to the British style, while the rest stays as `LANG` says.

`LC_ALL` is the big hammer: it overrides every `LC_*` at once, with no exception. `export LC_ALL=fa_IR.UTF-8` forces everything to that locale, and you can always `unset LC_ALL` afterwards.

#### LANG=C

`LANG=C` (the default "C" locale) is used in scripts to get predictable, consistent results everywhere, regardless of the machine's language. For example it makes `sort` use plain byte order and command output appear in default English, so a script behaves the same on every system.

#### Changing or adding locales

On Debian you generate locales with `dpkg-reconfigure locales`. The default is written in `/etc/locale.conf`:

```
# cat /etc/locale.conf
LANG="en_US.UTF-8"
```

With systemd, `localectl` reads the current locale, and `localectl set-locale LANG=en_US.UTF-8` sets it. You can also put a `LANG` line in `~/.profile` for just yourself.

### Character encoding

An encoding maps characters to bytes:

- **ASCII**: the original 7-bit scheme, 128 characters, enough for English letters, digits, and punctuation.
- **ISO-8859**: 8-bit sets that extend ASCII with accented and other-language characters, one set per language family (for example ISO-8859-1 for Western European).
- **Unicode / UTF-8**: **Unicode** is the universal character set covering every writing system plus symbols like ¾, ♠, and π. **UTF-8** is the modern way to encode it: variable-width, backward compatible with ASCII. Use UTF-8 unless you have a specific reason not to, and your system will work almost everywhere.

### iconv

`iconv` converts a file from one encoding to another. `-f` is "from", `-t` is "to", and `-l` lists all known encodings:

```
$ iconv -f WINDOWS-1258 -t UTF-8 /tmp/myfile.txt > /tmp/utf8.txt
```

You rarely need it now that UTF-8 is everywhere, but it is essential when you meet an old file in a legacy encoding.

### Summary

I split this into time and language. For time, `date` and `timedatectl` show the clock and zone, a timezone is an offset from UTC, and I set my personal zone with the `TZ` variable (or `env TZ=... date` for a one-off). The system zone comes from `/etc/localtime`, which I point at a file in `/usr/share/zoneinfo/`, with the plain-text name also in `/etc/timezone` on Debian. For language, the `locale` command lists the settings: `LANG` is the overall default, each `LC_*` tunes one aspect, and `LC_ALL` overrides them all. I keep `LANG=C` in mind for scripts, because it forces predictable byte-order sorting and default English output on any machine. Encodings run ASCII, then ISO-8859, then Unicode encoded as UTF-8, which is the sensible default, and `iconv -f ... -t ...` converts between them.
