# 107.3 Localisation and internationalisation

**Weight: 3**

Candidates should be able to localize a system in a different language than English. As well, an understanding of why LANG=C is useful when scripting.

**Objectives**

- Configure locale settings and environment variables.
- Configure timezone settings and environment variables.

**Terms**

`/etc/timezone`, `/etc/localtime`, `/usr/share/zoneinfo/`, `LC_*`, `LC_ALL`, `LANG`, `TZ`, `/usr/bin/locale`, `tzselect`, `timedatectl`, `date`, `iconv`, `UTF-8`, `ISO-8859`, `ASCII`, `Unicode`

### Locales

A **locale** is the set of rules for language and regional formatting: the language of messages, how dates and numbers look, currency, and sort order. A locale name has the form `language_TERRITORY.encoding`, for example `en_US.UTF-8` or `fr_FR.UTF-8`.

`locale` shows the current settings, and `locale -a` lists every locale installed:

```
$ locale
LANG=en_US.UTF-8
LC_NUMERIC="en_US.UTF-8"
LC_TIME="en_US.UTF-8"
LC_MONETARY="en_US.UTF-8"
...
$ locale -a
C
en_US.utf8
fr_FR.utf8
POSIX
```

### The locale variables

Several variables control locale, from broad to specific:

```
LANG        default for every category
LC_*        override one category (LC_TIME, LC_NUMERIC, LC_MESSAGES, ...)
LC_ALL      override everything, wins over LANG and every LC_*
```

`LANG` sets the baseline. A single `LC_*` overrides just its category, so you can keep English messages but French number formatting. `LC_ALL` is the big hammer that forces one locale everywhere, useful for a quick test.

```
$ date                          # in the fr_FR locale
lun. 7 sept. 2026 14:30:00 CEST
$ LC_ALL=C date                 # force the neutral C locale for one command
Mon Sep  7 14:30:00 CEST 2026
```

### Why LANG=C matters in scripts

The special locales `C` and `POSIX` mean "no localization": messages in plain English, ASCII sorting, predictable formats. Scripts should set `LANG=C` (or `LC_ALL=C`) so their output does not change with the machine's language. A script that greps for `No such file` will break on a French system where the message is translated, unless it forces the `C` locale first.

### Character encodings

An **encoding** maps characters to bytes.

- **ASCII** covers only the basic English characters, 7 bits.
- **ISO-8859** (Latin-1 and family) extends ASCII to 8 bits for Western European letters, but each variant covers only one region.
- **Unicode** is one character set for every writing system. **UTF-8** is its usual encoding, backward compatible with ASCII, and the modern default.

`iconv` converts a file from one encoding to another:

```
$ iconv -f ISO-8859-1 -t UTF-8 old.txt > new.txt
```

### Timezones

The system timezone is set by `/etc/localtime`, which is a copy of or a symlink to a file under `/usr/share/zoneinfo/`. Debian systems also record the name in `/etc/timezone`.

```
$ ls -l /etc/localtime
lrwxrwxrwx 1 root root 33 Sep  7 09:00 /etc/localtime -> /usr/share/zoneinfo/Europe/Paris
```

`tzselect` helps you find the right zone name interactively (it only prints the name, it does not apply it). The modern way to set the zone is `timedatectl`:

```
$ timedatectl set-timezone Europe/Paris
$ timedatectl
               Local time: Mon 2026-09-07 14:30:00 CEST
           Universal time: Mon 2026-09-07 12:30:00 UTC
                Time zone: Europe/Paris (CEST, +0200)
```

For a single command in a different zone, set `TZ`:

```
$ TZ='Asia/Tokyo' date
Mon Sep  7 21:30:00 JST 2026
```

### Summary

I split this into language and time. A locale is `language_TERRITORY.encoding` like `fr_FR.UTF-8`, and I inspect it with `locale`, listing what is installed with `locale -a`. `LANG` is the default, an `LC_*` variable overrides one category, and `LC_ALL` overrides them all, which is why I set `LC_ALL=C` in scripts so output stays plain English and predictable no matter the system's language. On encodings I know ASCII is 7 bit English, ISO-8859 is the 8 bit regional extension, and Unicode with UTF-8 is the universal modern default, converting between them with `iconv`. For time, the zone lives in `/etc/localtime` linked from `/usr/share/zoneinfo/`, I find a zone name with `tzselect`, set it with `timedatectl set-timezone`, and use the `TZ` variable to run a single command in another zone.
